## Система типов в PH8

Как и в PHP 8, в PH8 можно указывать типы аргументов функций и типы возвращаемых значений. 

Но философия здесь иная. 

В PHP 8 несовпадение типа считается ошибкой, а в PH8 объявленный тип служит подсказкой компилятору: он говорит виртуальной машине, **во что нужно превратить значение**.

Правила одинаковы для аргументов и для возвращаемых значений, так что тип гарантирован и на входе в функцию, и на выходе из неё.

### Скалярные типы

Допустим, функция объявлена так:

```php
function test(int $a, ?string $b) { /* ... */ }
```

Тогда вызов `test('66', 12)` совершенно корректен. Виртуальная машина приведёт строку `'66'` к числу `66`, поскольку первый аргумент объявлен как `int`, а число `12` превратит в строку `'12'`, так как второй аргумент имеет тип `?string`. С возвращаемыми значениями происходит то же самое: если функция с типом `: int` вернёт `'66'`, вызывающий код получит `66`.

### Отсутствие типа и nullable-типы

Если тип не указан, автоконвертация не выполняется: подразумевается тип `mixed`, и значение передаётся как есть.

Если тип объявлен как nullable (например, `?string`), конвертация применяется только к значениям, отличным от `null`. Сам `null` проходит без изменений.

### Тип `object`

Если передан (или возвращён) объект, он проходит как есть. Если же значение объектом не является, оно автоматически оборачивается в `stdClass($scalar_value)`. Таким образом, исходное значение не теряется, а код, ожидающий объект, всегда получает объект.

Это касается и `null`: если для параметра или возвращаемого значения типа `object` (без `?`) получен `null`, он тоже будет обёрнут в `stdClass(null)`. Чтобы `null` проходил без изменений, тип нужно объявить как `?object`.

### Тип `callable`

Значение считается корректным `callable`, если это строка или массив, указывающие на реально существующую функцию или метод, который можно вызвать. Например, строка `'strlen'` или массив `[$obj, 'method']`.

Если значение не удаётся привести к `callable`, оно заменяется вызовом специальной функции `__badcallable` из системной библиотеки. Для кода это полноценный `callable` (`is_callable()` вернёт `true`), но при первой же попытке вызова будет выброшено исключение `TypeError`, которое можно перехватить через `try/catch`.

Ошибка, таким образом, не теряется: она проявляется в момент использования некорректного значения, а не остаётся незамеченной.

### Итог

Благодаря единым правилам для входа и выхода PH8 всегда гарантирует соответствие типов. 
Достигается это не отказом с ошибкой, а разумным приведением значений к заявленным типам: скаляры 
конвертируются, не-объекты (включая `null`) оборачиваются в `stdClass`, а недопустимый `callable` 
превращается в заглушку, которая бросит исключение TypeError проблеме при вызове.
